1. Topic: Why did I receive exit code 130 during my COBOL lab?

   What I learned: I learned that exit code 130 usually means a process was interrupted, commonly by pressing Ctrl+C. During my first EC2 deployment, I received code 130 when using `echo $?`. 2. Topic: Why are COBOL return codes important?

   What I learned: Return codes help engineers understand whether an application completed successfully or encountered an error. During my COBOL exercises, code 0 meant success, 4 meant account not found, 8 meant a payment was rejected, and 12 meant a file error. Understanding these codes is important when troubleshooting banking applications and building automated systems.

3. Topic: Why do file paths matter when running COBOL programs?

   What I learned: I learned that file paths are important because applications need to locate their required files. During my lab, I ran the COBOL program from a different directory, which caused it to return code 12 because it couldn't locate `data/accounts.dat`. This helped me understand why the working directory matters when running Linux applications.

4. Topic: Why are Python virtual environments important?

   What I learned: Python virtual environments help manage application dependencies and prevent conflicts between different projects. During my fourth EC2 deployment, I received `uvicorn: command not found` because the application wasn't installed and configured yet. After completing the installation and activating the virtual environment, Uvicorn worked successfully.

5. Topic: Why is it important to deploy multiple EC2 instances?

   What I learned: Deploying multiple EC2 instances helps cloud engineers understand the process of building and configuring servers from scratch. During my homework, repeating the deployment made me more familiar with Linux commands, application installation, and troubleshooting errors. I learned that understanding how to repeat a deployment is important for building reliable cloud infrastructure.
